Eksperimen jmp rcx; int3; int3; ala stub cheat/game hooking

Di dunia reverse engineering, game modding, dan low-level debugging, kadang kita nemu pola instruksi seperti:

jmp rcx
int3
int3

atau:

jmp rax
nop
nop
nop

Sekilas kelihatan aneh. Kenapa setelah jmp masih ada instruksi lain padahal secara normal eksekusi gak bakal lanjut?

Ternyata pola begini sering dipakai buat:

  • trampoline stub
  • alignment
  • patch placeholder
  • anti-debug trick ringan
  • hotpatching
  • cheat/game hook stub
  • shellcode dispatcher
  • JIT stub
  • crash marker/debug marker

Basic Stub

Versi paling sederhana:

.intel_syntax noprefix
.global stub
.text

stub:
    jmp rcx
    int3
    int3

Kalau dipanggil:

void (*fn)() = stub;

maka CPU langsung lompat ke alamat di register RCX.

Instruksi int3 setelahnya sebenarnya unreachable dalam flow normal.

Kenapa Ada int3 Setelah jmp?

Debug Marker

int3 (0xCC) adalah software breakpoint.

Debugger seperti x64dbg, WinDbg, GDB bakal stop kalau CPU nyentuh byte ini.

Jadi kadang dipakai sebagai:

jmp rcx
int3
int3
int3

Artinya:

"kalau somehow flow nyasar ke sini, langsung breakpoint"

Padding

Kadang stub butuh ukuran tertentu.

Misalnya:

jmp rcx        ; 2 bytes
int3           ; 1 byte
int3           ; 1 byte

Total 4 byte.

Atau:

jmp rcx
nop
nop
nop
nop
nop

buat alignment ke boundary tertentu.

Hotpatch Area

Beberapa software sengaja nyisain byte setelah stub supaya nanti bisa di-overwrite runtime.

Contoh:

jmp rcx
int3
int3

Nanti patcher bisa ubah jadi:

jmp rcx
jmp other_place

atau overwrite full stub.

Implementasi Linux x86_64

Contoh full assembly:

.intel_syntax noprefix
.global _start
.text

payload:
    mov rax, 1
    mov rdi, 1
    lea rsi, [rip + msg]
    mov rdx, 6
    syscall

    mov rax, 60
    xor rdi, rdi
    syscall

stub:
    jmp rcx
    int3
    int3
    nop
    nop

_start:
    lea rcx, [rip + payload]
    call stub

msg:
    .ascii "hello\n"

Compile:

gcc -nostdlib -static test.s -o test

Flow: 

_start
  -> RCX = payload
  -> call stub
       -> jmp rcx
            -> payload

Instruksi int3 dan nop gak pernah dieksekusi.

Kenapa Cheat Engine / Injector Suka Pola Begini?

Karena gampang banget buat:

  • redirect flow
  • overwrite instruction
  • bikin trampoline
  • detour function
  • runtime patching
  • temporary hook

Misalnya:

Original:

mov eax, 1
add eax, ebx

Dispatch:

jmp my_stub
nop
nop

Lalu di my_stub:

; custom code

jmp return_address

Konsep begini dipakai di:

  • detours
  • instrumentation
  • profilers
  • anti-cheat
  • cheat
  • sandboxing
  • emulator
  • DBI (dynamic binary instrumentation)
